Diapositiva 19 · Cómo el computador resuelve una placa

De la teoría de placas al código FEM

Kirchhoff 1850 → Galerkin 1909 → Boeing 1956 → Hekatan 2026: el mismo loop, en distinta velocidad

175 años de teoría, condensados

1850
Kirchhoff
Hipótesis: las normales al plano medio permanecen rectas y perpendiculares tras deformar. Ecuación bi-armónica $\nabla^4 w = q/D$.
1945
Reissner-Mindlin
Generalización: las normales pueden rotar independiente del plano medio. Aparecen $\beta_x, \beta_y$ como GDL extras. Cubre placas gruesas.
1909
Galerkin
"En vez de resolver la PDE exacta, busquemos $w$ aproximado por combinación de funciones $\phi_i$." Nace el método de los residuos ponderados.
1956
Boeing / Turner / Clough
Discretizan el dominio en elementos pequeños. Cada uno aporta una matriz $K_e$ local. Las suman: nace el FEM industrial.

La pregunta del ingeniero estructural moderno no es "¿cómo se deduce la teoría?" (eso ya está hecho), sino "¿cómo el computador la usa para resolverme una placa?". Esta diapositiva responde eso paso a paso.

La ecuación que tenemos que resolver

Para una placa delgada (Kirchhoff) cargada con presión $q$ perpendicular al plano:

$$\frac{\partial^4 w}{\partial x^4} + 2\frac{\partial^4 w}{\partial x^2 \partial y^2} + \frac{\partial^4 w}{\partial y^4} = \frac{q(x,y)}{D}, \qquad D = \frac{E\,t^3}{12(1-\nu^2)}$$

Para una placa gruesa (Reissner-Mindlin), separamos en dos rotaciones independientes $\beta_x(x,y)$ y $\beta_y(x,y)$ + deflexión $w(x,y)$:

$$\boldsymbol{\kappa} = \begin{bmatrix} \partial_x \beta_x \\ \partial_y \beta_y \\ \partial_y \beta_x + \partial_x \beta_y \end{bmatrix}, \qquad \boldsymbol{\gamma} = \begin{bmatrix} \partial_x w - \beta_x \\ \partial_y w - \beta_y \end{bmatrix}$$

El computador no resuelve esa PDE directamente. La aproxima por una suma de funciones $\phi_i$ y resuelve un sistema lineal $\mathbf{K}\,\mathbf{u} = \mathbf{F}$. Eso es lo que viene.

El loop conceptual — 7 pasos para resolver una placa

1

Mallar la placa

Dividir el dominio rectangular en una grilla de pequeños cuadriláteros Q4. Cada uno tiene 4 nodos. Para una placa $10 \times 10$ m con $16 \times 16$ elementos → 256 elementos, 289 nodos.

2

Asignar grados de libertad por nodo

Cada nodo guarda 3 incógnitas en placas Mindlin: $(w, \beta_x, \beta_y)$. Total de incógnitas globales: $3 \times 289 = 867$ GDL.

3

Funciones de forma Q4 bilineares

Dentro de cada elemento, $w(\xi, \eta) \approx \sum_{i=1}^4 N_i(\xi,\eta)\, w_i$ con $N_i = \frac{1}{4}(1+\xi_i\xi)(1+\eta_i\eta)$. Lo mismo para $\beta_x$ y $\beta_y$. Estas $N_i$ permiten interpolar el campo dentro del elemento usando solo los 4 valores nodales.

4

Matriz B (relación deformación-desplazamiento)

Las curvaturas $\boldsymbol{\kappa}$ y cortantes $\boldsymbol{\gamma}$ se calculan derivando las $N_i$: $\boldsymbol{\kappa} = \mathbf{B}_b \cdot \mathbf{d}_e$, $\boldsymbol{\gamma} = \mathbf{B}_s \cdot \mathbf{d}_e$. Aquí $\mathbf{B}_b$ es $3 \times 12$ y $\mathbf{B}_s$ es $2 \times 12$ porque hay $4 \text{ nodos} \times 3 \text{ GDL} = 12$ GDL por elemento.

5

Matriz de rigidez elemental $\mathbf{K}_e$ (12×12)

Por el principio del trabajo virtual: $\mathbf{K}_e = \int_{\Omega_e} \mathbf{B}_b^T\,\mathbf{D}_b\,\mathbf{B}_b\,d\Omega + \int_{\Omega_e} \mathbf{B}_s^T\,\mathbf{D}_s\,\mathbf{B}_s\,d\Omega$.
La integral se evalúa por cuadratura de Gauss: bending con $2{\times}2$ puntos (full integration), shear con $1{\times}1$ (reduced integration, "SRI") para evitar shear locking.

6

Ensamblaje global → $\mathbf{K}\,\mathbf{u} = \mathbf{F}$

Un solo doble-bucle (igual que Diapositiva 08): para cada elemento, sumar su $\mathbf{K}_e$ en la matriz global $\mathbf{K}$ usando el mapeo local → global. Los nodos compartidos por varios elementos suman sus contribuciones. La matriz resultante es sparse: solo los nodos vecinos generan entradas no-cero.

7

Aplicar BC y resolver

Para placa simplemente apoyada en los 4 bordes, imponer $w=0$ en los nodos del borde (método penalty: $K_{ii} \mathrel{+}= 10^{20}$). Resolver el sistema lineal con scipy.spsolve (Python), K\F (Julia), K\F (MATLAB) o Eigen::SparseLU (C++). Obtenemos las 867 incógnitas $\mathbf{u}$.

El loop concreto — 3 lenguajes lado a lado

Mismo algoritmo, mismas variables, mismo orden de operaciones. La diferencia es sintaxis y runtime.

Python (validacion/python-fem/)
K = lil_matrix((n_dof, n_dof))
F = np.zeros(n_dof)

for e in range(n_elems):
    nc = coords[elements[e]]
    Ke = element_stiffness(nc)
    fe = element_load(nc, q)
    dof_map = [3*n+d for n in elements[e]
                       for d in range(3)]
    for ii in range(12):
        F[dof_map[ii]] += fe[ii]
        for jj in range(12):
            K[dof_map[ii],
              dof_map[jj]] += Ke[ii, jj]

# BC penalty + solve
K = K.tocsr()
u = spsolve(K, F)
Julia (validacion/julia/)
I_rows, J_cols, K_vals = Int[], Int[], Float64[]
F = zeros(n_dof)

for e in 1:n_elems
    nc = coords[elements[e, :], :]
    Ke = element_stiffness(nc)
    fe = element_load(nc, q)
    dof_map = vcat([[3*(elements[e,i]-1)+d
                     for d in 1:3]
                     for i in 1:4]...)
    for ii in 1:12
        F[dof_map[ii]] += fe[ii]
        for jj in 1:12
            push!(I_rows, dof_map[ii])
            push!(J_cols, dof_map[jj])
            push!(K_vals, Ke[ii, jj])
        end
    end
end
K = sparse(I_rows, J_cols, K_vals,
           n_dof, n_dof)
# BC penalty + solve
u = K \ F
MATLAB (Matlab/Rectangular_Slab_FEA.m)
K = zeros(n_dof, n_dof);
F = zeros(n_dof, 1);

for e = 1:n_elems
    nc = coords(elements(e, :), :);
    Ke = element_stiffness(nc);
    fe = element_load(nc, q);
    dof_map = zeros(1, 12);
    for i = 1:4
        for d = 1:3
            dof_map(3*(i-1)+d) = ...
              3*(elements(e,i)-1)+d;
        end
    end
    for ii = 1:12
        F(dof_map(ii)) = ...
          F(dof_map(ii)) + fe(ii);
        for jj = 1:12
            K(dof_map(ii), dof_map(jj)) = ...
              K(dof_map(ii), dof_map(jj)) ...
              + Ke(ii, jj);
        end
    end
end
% BC penalty + solve
u = K \ F;

↑ El bucle for e = 1:n_elems es la columna vertebral del FEM. Sin él, el computador no sabría qué hacer. ↑

Por qué funciona — la "magia" del loop revisitada

Una placa real con $200 \times 200$ elementos tiene 40,000 elementos × 144 = 5.76 millones de sumas. A mano sería físicamente imposible. El computador lo hace en milisegundos porque:

  • El loop for e = 1:n_elems se vectoriza (en numpy/Julia) o se compila a SIMD (en C++).
  • La matriz $\mathbf{K}$ es sparse: solo ~1% de entradas son no-cero. El solver SparseLU explota eso.
  • Las funciones $N_i$ y la cuadratura de Gauss son fórmulas cerradas conocidas hace 200 años. El computador las evalúa en aritmética IEEE 754.
  • El método matemático no cambió entre Galerkin 1909 y Hekatan 2026. Solo cambió la velocidad de ejecución.
Conclusión: programar una placa por FEM es traducir una integral de variables continuas en una suma finita de matrices locales, y ensamblarlas con un bucle. Lo difícil no es la matemática (ya está resuelta desde 1909). Lo difícil es ejecutar el bucle suficientemente rápido para que el ingeniero modelo, vea resultados, y vuelva a modelar — en segundos. Esa es la apuesta de Hekatan Struct: WebAssembly hace ese bucle en el navegador.
